    URLから記事を作る（そのまま公開）

    Amazon・楽天市場・Yahoo!ショッピングの商品ページURLを貼り付けると、 商品名を読み取り、本文をAIで作ってそのまま公開します（画像は付きません）。 「記事」タブの下書き作成とは違い、途中で内容を確認する画面はありません。 禁止表現・使えないタグなどの要確認点が見つかった場合は、その部分を取り除いて自動で整えてから公開します （取り除いても直らない問題が残ったときだけ、下書きのまま保存します）。 カテゴリーは商品名から自動で推測するため、外れていた場合は 「記事」タブから直してください。

    Amazonはボット判定で商品ページの取得がブロックされやすく、その場合は商品名を取得できずに失敗します。 ここに商品名を入力しておくと、ページの取得を行わずこの名前で記事を作ります。 楽天市場・Yahoo!ショッピングは通常どおり自動取得できます（入力すればそちらもこの名前を優先します）。
    Amazonは商品ページのURL（/dp/ など）が必要です。短縮リンク（amzn.to）は使えません。
    本文の生成には「画像」タブで登録した Gemini または Claude のAPIキーが要ります。 アイキャッチ画像はここでは作りません。必要であれば公開後に「記事」タブ・「画像」タブから追加してください。
    GitHubとの接続（「接続」タブ）もあらかじめ済ませておいてください。 
    URLを入力して実行してください。

    記事を編集

    「プロンプトで本文を作る」は、docs/article-prompt.md をそのまま送って本文一式を作ります。 リード・良い点・注意点・場面・スペック表・口コミと対策・まとめ・メタ情報・タグ・サブカテゴリーが埋まります。 アイキャッチ画像が無い記事は、あわせて画像も作ります（「画像」タブのプロンプトを使用）。
    できあがったら禁止表現・文字数・使えないタグを自動で検査し、引っかかった点を知らせます。 そのまま公開せず、必ず内容を読んでから保存してください。

    入力はブラウザ内に保持されます。サイトに反映するには、記事一覧に戻って「変更をまとめて公開」を押してください。何本でも一度に公開でき、ビルドは1回で済みます。

    画像なし
    選んだ画像は自動で1200px・WebPに圧縮してからGitHubへ保存します。
    画像を設定したあとは、記事を保存し、記事一覧の「変更をまとめて公開」を押すとサイトに反映されます。
    画像のアップロードだけではビルドが走りません（配信側のビルド回数を節約するため）。

    7. アフィリエイトボタン

    記事内3か所と、スマホ下部の追従ボタンに使われます。

    Amazonの商品ページURLをそのまま貼り付けてください。ASINを自動で抜き出します。
    /dp/ /gp/product/ モバイル版など主要な形式に対応しています。 短縮リンク（amzn.to）は展開が必要なため、ブラウザで開いてから本来のURLを貼ってください。
    アソシエイトIDは「サイト設定」で一括管理され、リンクは https://www.amazon.co.jp/dp/{ASIN}?tag={ID} の形で自動生成されます。 ID変更時も全記事へ自動反映されるため、記事ごとに貼り直す必要がありません。
    商品パッケージのバーコードの数字、またはメーカー製品ページに載っています。 楽天とYahoo!は同じ商品を多数の店舗が出しているため、型番だけでは同一商品と確定できません。 JANコードで検索すると、構成が同じ商品ページを確実に特定できます。リンク切れ検査でも使います。
    入れると、本文生成時に公式ページの内容を参考に渡し、記事のスペック表の下に 「メーカー公式サイトで仕様を確認する」参照リンク（nofollow）を表示します。 Amazon・楽天・Yahoo!のURLは入れないでください。
    商品画像つきのリンクカードは、この3か所とは別枠で本文の後半に自動で入ります。アイキャッチ画像を設定している記事にだけ出ます。
    入力したショップのボタンだけが記事に並びます。その商品が売っていないショップは空欄のままにしてください。
    検索結果ページのURLは入れないでください（購入率が大きく下がります）。商品ページのURLだけを貼ります。
    リンクは もしもアフィリエイト 経由に自動で変換されます（IDは「サイト設定」で管理）。

    結論ボックス

    ファーストビューに表示される最重要パートです。読者はここだけ読んで離脱することもあります。

    1. 買わないほうがいい人

    記事の最優先パートです。ここで合わない読者を先に切ることで、残った読者の成約率と満足度が上がります。

    2. この商品で変わる「実際の生活シーン」

    スペックではなく、購入後にストレスが減る具体的な場面を書きます。3つが基本です。

    3. メリット・デメリット

    デメリットを正直に書くほど成約率は上がります。空欄にするとボックス自体が非表示になります。

    4. スペック比較表

    1行目が見出し行です。2列目が自社推し列としてハイライトされます。行は「項目名, 値1, 値2, 値3」のようにカンマ区切りで入力してください。

    記事スラッグを入れると、その商品の個別レビューへ「詳しいレビュー →」のリンクが出ます。
    逆にレビュー記事側にも「この商品を比較した特集」が自動で表示されます。空欄の項目は省略できます。
    ◎○△×は <span class="mark-o">◎</span> のように書くと色が付きます。空欄にすると比較表セクションごと非表示になります。

    5. 共通の不満点と対処法

    口コミの不満点を挙げ、その対策を示すセクションです。購入不安の払拭に効きます。

    6. レビューから見えたこと

    利用者の声を読み込んで気づいた、スペック表からは分からないポイントを書きます。 「自分が使った」という書き方は避け、レビューを整理した内容として書いてください（実際に使用した商品の場合は、その旨を明記すれば問題ありません）。

    8. 次に困りそうなこと・関連提案

    「この商品を導入すると、次に〇〇が発生しやすくなります」という切り口で回遊導線を作ります。リンク先は実在する記事にだけ設定してください（空欄ならテキストのみ表示されます）。

    プレビューで分かること・分からないこと

    分かること

    • 記事カードの見出し・抜粋・アイキャッチ・種類バッジ（レビュー／特集／選び方）
    • 記事ページの大見出し
    • スマホ・タブレット・PC それぞれの幅での崩れ

    分からないこと

    • 本文の中身や目次（ページを組み立てるのは公開時のため）
    • 新しく作った記事（まだページが無いので、既存ページの上には出せません）

    本文の見え方だけを確かめたいときは、「編集」タブの「記事プレビュー」を使ってください。

    記事にする商品を探す

    サイトの公開状態

    メンテナンス中にすると、全ページが「準備中」画面（503）に切り替わります。管理画面はそのまま使えるので、ここから戻せます。

    切り替えは GitHubに保存 → 自動ビルド → 反映 の順に進むため、実際に切り替わるまで1〜2分かかります。
    検索エンジンには「一時的な停止」として伝わる形（503）なので、この状態でインデックスされることはありません。

      基本設定

      ここでの変更は全ページのヘッダー・フッター・メタ情報に反映されます。

      カテゴリーの写真

      トップページのカテゴリー枠に出す写真です。1カテゴリーにつき1枚を固定します。 決めていないあいだは、そのカテゴリーの最新記事の写真で代用されるので、 記事が増えるたびに絵が入れ替わります。

      選んだ画像は1200px・WebPに圧縮してからGitHubへ保存します。 写真を選んだあと、このタブの「GitHubに保存して反映」を押すとサイトに出ます（どのカードのボタンでも構いません）。

      Amazonアソシエイト

      ここに入れたIDが、ASINを設定している全記事のリンクへ自動で付与されます。

      審査前は空欄のままで構いません。空欄のあいだはタグ無しの通常リンクが生成され、 IDを入れた時点で全記事のリンクに一括で付与されます。
      アソシエイト審査には「180日以内に3件の適格販売」が必要です。記事を数本公開してから申請してください。

      機能のON / OFF

      必要になったときにチェックを入れるだけで、該当ページ・パーツが生成されます。

      GitHub Pages はサーバー処理ができないため、外部サービスの受信URLが必要です。
      無料で使える代表例：Formspree（月50件まで無料）／Googleフォーム（無制限・デザインは埋め込み）／Cloudflare Workers。
      未設定のあいだは、フッターのメールリンクだけが表示されます。

      広告（Google AdSense）

      Googleが配るコードは書き換えません。ここで決めるのは出す・出さないと置き場所だけです。

      「位置を自分で決める」は、AdSense管理画面で作った広告ユニットのID（スロットID）を下に入れた場所にだけ出ます。空欄の枠は出ません。
      「自動広告」はGoogleが場所を選ぶので手間はかかりませんが、読みかけの本文に割り込むことがあります。
      置き場所は「メリット・デメリットの直後」「関連記事の下」「PCサイドの最下部」の3か所です。購入ボタンの近くには置きません（どちらを押したのか分からなくなり、規約上もリスクになるため）。
      ads.txt と所有確認のメタタグは、パブリッシャーIDを入れておけば自動で出力されます。

      ASPの広告（A8.net・バリューコマースなど）

      ASPで取得した広告リンクをそのまま貼る枠です。コードは書き換えません（規約）。決めるのは置き場所と、どのカテゴリーの記事に出すかだけです。

      複数のバナーを入れ替えたいときは、コードを続けて貼るだけで構いません（--- だけの行で区切ってもOK）。ASPのリンクの始まりを見て自動で1件ずつに分け、表示のたびに1つが選ばれます。
      A8の「広告リンク」ページからまとめて取り出す道具を tools/a8-collect.js に用意しています（開発者ツールのコンソールに貼るだけで、そのページの全コードがクリップボードに入ります）。選ばれなかったコードは画像も計測用の画像も読み込まれないので、表示回数が水増しされません。
      「PR」の表示は自動で付きます（ステマ規制の対応）。
      記事の下＝関連記事の下に出ます。PCサイド＝ランキングの下に出ます（スマホでは出ません）。
      対象カテゴリーを選ばないと、すべての記事に出ます。記事の内容と関係のない広告は成果が出にくいので、ジャンルを合わせてください。

      記事の自動作成—

      毎朝5時にGitHub Actionsが動きます。ここで決めた回数の日だけ、候補集め→本文→レビュー→公開まで進みます。オフのあいだは、手動で動かしても記事は作られません。

      公開まで自動にすると、出来上がった記事はそのままサイトに出ます。出したくない記事は、公開後にこの管理画面の「記事」タブで下書きに戻してください。
      レビュー基準は docs/review-rules.md（禁止表現＋ダークパターン）。基準を満たさなかった記事は下書きのまま残ります。
      オフにすると、下書きはプルリクエストで止まり、公開は手作業になります。
      ここで決めた本数に達したサブカテゴリーは、ビルド時に「特集を作る目安に達したジャンル」として通知されます。特集記事はカテゴリー「特集・まとめ」で作成してください。
      ここに入れた期間だけ、サイト上部に「現在○○開催中！」の告知が流れます。期間外は何も表示されません。
      Amazonはセール日程を機械的に配布していないため、発表されたら手で追加してください。日付の判定は閲覧時のブラウザが行うので、期間に入れば再ビルドなしで表示されます。
      APIキーはこの画面には入力しないでください。この管理画面はGitHubへコミットする仕組みのため、 入力するとキーが公開リポジトリに残ります。
      キーは GitHub の Settings → Secrets and variables → Actions に GEMINI_API_KEY として登録してください。ローカルで実行する場合は export GEMINI_API_KEY=... を使います。
      生成は python3 tools/make_images.py --all、または Actions の 「Generate article images」から実行します。

      Google Analytics

      測定IDを入力して保存すると、全ページの <head> に GA4 のタグが自動で挿入されます。

      取得手順：Google Analytics → 管理 → プロパティを作成 → データストリーム → ウェブ → サイトURLを入力 → 表示される「測定ID」をコピー。

      Google Search Console

      HTMLタグでの所有権確認に使うコードです。保存すると全ページに meta タグが挿入されます。

      取得手順：Search Console → プロパティを追加 → 「URLプレフィックス」を選択 → 所有権の確認で「HTMLタグ」を開く → content="…" の中身をコピー。
      保存・デプロイ後に「確認」を押してください。確認後、サイトマップに sitemap.xml を送信します。

      アクセス状況

      GA4から取り込んだ記事別のアクセス数です（content/ranking.json）。毎日5:00に自動更新され、サイトのランキングとHotバッジもこの値で並びます。

      GA4を開く
      「最新を読み込む」を押してください。

      公開後のチェックリスト

      • Search Console でサイトマップ（sitemap.xml）を送信した
      • Analytics のリアルタイムで自分のアクセスが計測された
      • Amazonアソシエイトに独自ドメインを登録した
      • プライバシーポリシーにアクセス解析の記載がある（自動で入っています）
      • スマホの実機で、追従ボタンとカテゴリナビの表示を確認した

      この画面の鍵

      管理画面は Cloudflare Access（Zero Trust） が守っています。認証を通っていない人は、URLを直接開いてもこのページに到達できません。

      ログインできる人の管理
      Zero Trust ダッシュボード → Access → アプリケーション → モノベース管理画面 のポリシーで、 許可するメールアドレスを追加・削除できます。

      パスキーで開きたいとき
      同じアプリの「ログイン方法」に Google などを追加すると、そのアカウントのパスキー（Touch ID・Face ID）で認証できます。

      Yahoo!のAPIはブラウザから直接呼べないため、このサイトの /api/yahoo を経由します。 「URLから記事を作る」タブが商品ページを取得する /api/fetch-product も同じ仕組みです。 どちらの入口も Cloudflare Access を通ったリクエストしか受け付けません。 Zero Trust のアプリケーションで、見張る対象のパスに /api/ を追加しておいてください。

      GitHub との接続

      この画面から直接コミットするための設定です。入力内容はこのブラウザ内（localStorage）にのみ保存され、外部に送信されるのは GitHub API だけです。

      ユーザー名・リポジトリ名・ブランチは設定済みです。
      トークンを貼り付けて「接続する」を押すだけで使えます。一度接続すればこのブラウザに記憶されます。
      トークンの作り方（必ず権限を絞ってください）
      GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token
      ・Repository access：Only select repositories でこのリポジトリだけを選択
      ・Permissions：Contents = Read and write のみ（他は不要）
      ・Expiration：90日など期限を必ず設定
      このトークンは他人と共有しないでください。共有PCでは使用後に「接続を解除」を押してください。 
      まだ通信していません。

      スマホなど他の端末でも同じ設定で使う

      GitHubトークンやAPIキーは、この端末のブラウザ内（localStorage）にだけ保存されており、 別の端末で開いても自動では共有されません。QRコードで渡すと、入力し直さずに済みます。

      QRコードにはトークン・APIキーがそのまま入っています。パスワードと同じ扱いにしてください。 画面の写真を撮って共有したり、他人に見せたりしないでください。読み取ったら「隠す」で消してください。
      スマホのカメラでこのQRコードを読み取り、出てきたリンクを開いてください。 「接続情報を取り込みますか」の確認のあと、この画面がスマホにも表示されます。

      オフラインで使う場合

      GitHubに接続せず、編集結果をファイルとして書き出すこともできます。書き出した JSON を content/ に置いて python3 build.py を実行してください。

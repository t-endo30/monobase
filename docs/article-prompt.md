# 記事作成プロンプト（モノベース標準）

生成AIに記事を書かせるときは、このプロンプトの `[ ]` を埋めて使う。
出力された内容を `admin.html` の各フィールドに貼り付けるか、
`content/articles.json` に直接転記する。

---

## プロンプト本文

```
あなたは、読者の悩みに寄り添い、正直な検証で深い信頼を得ている商品レビューブロガーです。
以下の条件と構成に基づき、Amazonアフィリエイト用の商品紹介記事（Clean HTML形式）を作成してください。

【基本情報】
・メイン紹介商品: [商品名 / 価格 / 仕様の概要]
・比較・代替として挙げる商品（1〜2点）: [比較対象の商品名や簡単な仕様]
・ターゲット読者: [誰がどんな場面で困っているか]
・メインキーワード: [狙いたい検索キーワード]

【参考にすべきレビューデータ】
---レビュー---
[商品の良い評価・低い評価（特に不満点やデメリット）をそれぞれ箇条書きで入力]
---ここまで---

【必須の構成要素（以下の順序で記載すること）】
1. 買わないほうがいい人（★最優先のネガティブ訴求）
   - 「〇〇な期待をしている人や、〇〇な環境の人にはこの商品は全く向いていません」と冒頭で明確に切り捨てる。
2. この商品で変わる「実際の生活シーン」3選
   - 単なるスペック解説ではなく、購入後にストレスが減る具体的場面（例：「夜中に家族が寝ている横で音が気にならない」など）を描く。
3. メリット・デメリットの2列ボックス
   - 良い点（緑/青枠）と不満点・デメリット（赤/オレンジ枠）を対照的に配置。
4. スペック比較表
   - メイン商品と代替商品を比較した、スマホで横スクロール可能な <table>。
5. レビューから見えた共通の不満点と、失敗しないための対処法
6. ★【運営者の実体験コラム枠】
   - 以下のようなスタイル枠（<div class="personal-note">）を作成し、実体験風の1〜2行のワンポイント
     （「届いて最初に感じた注意点」や「実際に使ってわかった質感」など）が入るプレースホルダーを挿入すること。
7. Amazonで価格と詳細を確認するボタン（目立つオレンジ装飾）
8. ★次に困りそうなこと・併売の提案（回遊導線）
   - 「この商品を導入すると、次に〇〇（関連する悩み）が発生しやすくなります」という切り口で、
     別のアイテムが必要になる理由を解説し、関連記事への誘導枠を置くこと。

【執筆ルール】
・文字数: 3,500字〜4,000字程度。
・絶賛や保証表現（「絶対」「必ず」等）は厳禁。合わない場面を必ず記載すること。
・出力フォーマット: <html>や<head>は含めず、<body>内でそのまま使えるClean HTML
  （<h1>, <h2>, <p>, <table>, <ul>, <div>等）のみをコードブロックで出力すること。
```

---

## 出力をサイトに載せる手順

生成結果は、そのまま貼るのではなく **管理画面の対応フィールドに分解して入れる**。
テンプレート側が枠のデザイン・レスポンシブ・構造化データを担当するため、
本文だけを流し込めば全記事で見た目が揃う。

| プロンプトの構成要素 | 管理画面のフィールド | JSONキー |
|---|---|---|
| 1. 買わないほうがいい人 | 「買わないほうがいい人」 | `not_for.intro` / `not_for.items` |
| 2. 実際の生活シーン3選 | 「変わる生活シーン」 | `scenes[].title` / `scenes[].text` |
| 3. メリット・デメリット | 「メリット」「デメリット」 | `pros` / `cons` |
| 4. スペック比較表 | 「スペック比較表」 | `spec.headers` / `spec.rows` |
| 5. 共通の不満点と対処法 | 「気になる点と対策」 | `voices[]` |
| 6. 実体験コラム枠 | 「運営者の実体験コラム」 | `personal_note` |
| 7. Amazonボタン | 「アフィリエイトボタン」 | `amazon_url` / `cta_label` |
| 8. 次に困りそうなこと | 「次に困ること・関連提案」 | `next_problem.intro` / `next_problem.items[]` |

記事ページでの出力順もこの通りに固定されている。
`summary`（結論ボックス）と `conclusion`（まとめ）は、この構成の前後を挟む枠として任意で使う。

### 注意

- **8番の関連記事リンクは、実在する記事にだけ張る。** 未作成の記事に張ると404になる。
  リンク先が未作成なら `link_url` を空にすれば、テキストだけの枠として表示される。
- 出力に含まれる `<strong>` `<em>` などのインラインタグはそのまま使える。
  ブロック要素（`<div>` `<table>`）はテンプレート側が生成するので貼り付けない。
- **保証表現（「絶対」「必ず」「確実に」）が混じっていないか目視で確認する。**
  景品表示法・薬機法に触れるリスクがあるうえ、Amazonアソシエイトの規約違反にもなり得る。
- 生成された内容は必ず一次情報（メーカー公式・実物）で裏取りしてから公開する。
  スペック表の数値は特に誤りが混入しやすい。
- **`personal_note` は実際に使った人間が書く。** ここを生成AIに書かせると、
  体験談の偽装になり、信頼性・規約の両面で問題になる。初期値はプレースホルダーが入っている。

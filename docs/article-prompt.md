# 記事作成プロンプト（モノベース標準）

生成AIに記事を書かせるときは、このプロンプトの `[ ]` を埋めて使う。
出力された内容を `admin.html` の各フィールドに貼り付けるか、
`content/articles.json` に直接転記する。

---

## このサイトの記事の性格

**「欠点も書くから、褒めているところが信用できる」** というのが当サイトの売りです。
欠点の指摘は信頼を作るための手段であって、目的ではありません。

したがって記事の重心は **良い点の側** に置きます。

- 良い点は、具体的な場面まで踏み込んで **とことん持ち上げる**
- 欠点は、**当てはまる人を絞り込んで短く** 書く（「合う人には関係のない話」だと分かる形にする）
- 読み終わったときに残る感情は「不安」ではなく **「これ、自分の環境なら効くな」**

分量の目安は **良い点 7 : 注意点 3**。
「買わないほうがいい人」は読者をふるいにかける枠であって、
商品を否定する枠ではありません。ここを抜けた読者には、
そのあと迷いなく背中を押すこと。

## プロンプト本文

```
あなたは、読者の悩みに寄り添い、正直な検証で深い信頼を得ている商品レビューブロガーです。
以下の条件と構成に基づき、Amazonアフィリエイト用の商品紹介記事を作成してください。

【基本情報】
・メイン紹介商品: [商品名 / 価格 / 仕様の概要]
・比較・代替として挙げる商品（1〜2点）: [比較対象の商品名や簡単な仕様]
・ターゲット読者: [誰がどんな場面で困っているか]
・メインキーワード: [狙いたい検索キーワード]

【参考にすべきレビューデータ】
---レビュー---
[商品の良い評価・低い評価（特に不満点やデメリット）をそれぞれ箇条書きで入力]
---ここまで---

【トーン（最重要）】
・良い点と注意点の分量は 7:3。良い点のほうを厚く書く。
・良い点は「機能の説明」で終わらせず、その機能によって
  読者の一日がどう変わるかまで書き切る。
  × 「ガススプリング式で上下に動かせます」
  ○ 「片手で画面を下げられるので、日によって変わる座り方に机のほうを合わせられます。
      夕方に首が疲れてきたと感じた瞬間、その場で直せる。これは固定スタンドでは選べない体験です」
・「戻れなくなる」「一度知ると元の状態が我慢できなくなる」といった、
  導入後の変化の大きさを言葉にしてよい。
・注意点は、当てはまる人を明確に限定して書く。
  「この商品の弱点」ではなく「この環境の人には合わない」という書き方にする。
・断定・保証表現は使わない（後述の禁止語）。持ち上げるのは体験の描写で行い、
  「絶対に満足できます」のような保証はしない。

【必須の構成要素（以下の順序で記載すること）】
1. ★【ここが効く】（良い点を先に、強く）
   - 3項目。それぞれ見出し1行＋本文3〜4行。
   - 「この商品を選ぶ理由」を、生活の場面に落として書く。
   - 記事の中で最も熱量の高い部分にすること。
2. 買わないほうがいい人（読者のふるい分け）
   - 「〇〇な期待をしている人や、〇〇な環境の人には向きません」と条件で切る。
   - 商品を貶さない。あくまで環境との相性の話として書く。
   - 5項目以内、各1〜2行に収める。長く書かない。
3. この商品で変わる「実際の生活シーン」3選
   - 購入後にストレスが減る具体的場面を描く。ここも良い点側の枠。
4. メリット・デメリットの2列ボックス
   - メリットは5項目、デメリットは5項目。ただしデメリットは
     「対処できるもの」「相性の問題」であることが分かる書き方にする。
5. スペック比較表
   - メイン商品と代替商品を比較した、スマホで横スクロール可能な表。
6. ★【ライターの地の文セクション（2〜3本）】
   - 見出し＋3〜4段落。表や箇条書きでは伝わらない判断の根拠を書く。
   - うち1本以上は「この商品の良さがどこから来るのか」を掘り下げる回にする。
   - レビューを読み込んだライターの視点として、はっきりした主観を入れてよい。
     「正直に言えば」「これは強い」「勧められます」「価格差は納得できます」など。
   - ただし「私が使ったところ」という実体験の捏造はしない。
7. 共通の不満点と、失敗しないための対処法
   - 不満を挙げっぱなしにしない。必ず対処法とセットにして、
     「知っていれば起きない」と読者が思える形で閉じる。
8. ★【レビュー分析コラム枠】
   - 購入者レビューを読み込んで見えた1〜2行のワンポイント。
   - 「自分が使った」という一人称の体験談としては書かないこと。
9. Amazonで価格と詳細を確認するボタン
10. ★次に困りそうなこと・併売の提案（回遊導線）
11. まとめ（3段落）
   - 1段落目：どんな人に向くかの再確認
   - 2段落目：★導入後の変化を、いちばん強い言葉で書く（記事の山場）
   - 3段落目：向かない人への短い一言と、確認すべき点

【執筆ルール】
・文字数: 6,000字〜8,000字。うち4割以上は表や箇条書きではなく地の文（段落）にすること。
・絶賛や保証表現は禁止。次の語は使わない：
  絶対／必ず／確実に／保証します／間違いなく／100%／誰でも／永久に／完治／業界No.1／日本一／
  「最安値です」「業界最安」「日本最安」
  （「1.5倍の余裕を見る」「事前に確認する」のように言い換える）
・一人称の体験談（「私が使ったところ」）は書かない。主観は「評価」として書く。

【出力フォーマット（重要）】
・使ってよいHTMLタグは <strong> と <em> の2つだけ。文章の中に直接書く。
・<p> <div> <ul> <li> <table> <h2> などのブロック要素は書かない。
  枠組みはサイト側のテンプレートが作るため、貼り付けると二重になる。
・&lt; &gt; &amp; のような実体参照を書かない。タグは生の < > で書く。
・出力全体をコードブロック（```）で囲まない。
・見出しや箇条書きは、後述の項目ごとに分けて出力する（Markdown記法は使わない）。
```

## 出力をサイトに載せる手順

生成結果は、そのまま貼るのではなく **管理画面の対応フィールドに分解して入れる**。
テンプレート側が枠のデザイン・レスポンシブ・構造化データを担当するため、
本文だけを流し込めば全記事で見た目が揃う。

| プロンプトの構成要素 | 管理画面のフィールド | JSONキー |
|---|---|---|
| 1. ここが効く | 「ここが効く」 | `highlights.heading` / `highlights.intro` / `highlights.items[]` / `highlights.after` |
| 2. 買わないほうがいい人 | 「買わないほうがいい人」 | `not_for.intro` / `not_for.items` / `not_for.after` |
| 3. 実際の生活シーン3選 | 「変わる生活シーン」 | `scenes[].title` / `scenes[].text` |
| 4. メリット・デメリット | 「メリット」「デメリット」 | `pros` / `cons` |
| 5. スペック比較表 | 「スペック比較表」 | `spec.headers` / `spec.rows` |
| 6. ライターの地の文 | 「本文セクション」 | `sections[].heading` / `sections[].paras[]` / `sections[].aside` |
| 7. 共通の不満点と対処法 | 「気になる点と対策」 | `voices[]` |
| 8. レビュー分析コラム枠 | 「レビューから見えたこと」 | `personal_note` |
| 9. Amazonボタン | 「アフィリエイトボタン」 | `amazon_url` / `cta_label` |
| 10. 次に困りそうなこと | 「次に困ること・関連提案」 | `next_problem.intro` / `next_problem.items[]` |
| 11. まとめ | 「まとめ」 | `conclusion`（配列で3段落） |

記事ページでの出力順もこの通りに固定されている。
`summary`（結論ボックス）は記事の先頭に出る。

### 地の文を入れられる場所

比較表と箇条書きだけの記事は読み物にならないため、次のキーに段落を足せる。
いずれも文字列でも配列でも書ける（配列にすると段落が分かれる）。

| キー | 出る場所 |
|---|---|
| `lead` | 記事冒頭。2〜3段落 |
| `highlights.intro` / `highlights.after` | 「ここが効く」の前後 |
| `not_for.after` | 「買わないほうがいい人」の枠のすぐ下 |
| `scenes_intro` / `scenes_after` | 生活シーンの前後 |
| `proscons_note` | メリット・デメリットの下。どちらが効くかの評価 |
| `spec.read` | スペック比較表の下。表の読み方 |
| `sections[]` | 独立した見出し付きセクション。地の文の主戦場 |
| `voices_after` | 気になる点と対策のあと |
| `conclusion` | まとめ。配列で3段落 |

### 注意

- **10番の関連記事リンクは、実在する記事・カテゴリーページにだけ張る。**
  `tools/check_articles.py` がリンク切れを検出して止める。

- **HTMLは `<strong>` と `<em>` だけ。** ブロック要素はテンプレート側が生成する。
  貼り付けると枠が二重になり、レイアウトが崩れる。
  タグがそのまま文字として表示された場合は `tools/check_text.py` が検出する。

- **主観は書くが、体験は捏造しない。** レビューと仕様を読み込んだライターとして
  「正直に言えば」「勧められます」「戻れなくなる部類です」といった判断は積極的に書いてよい。
  一方で「私が使ったところ」という実体験の描写は、実機を使っていない限り書かない。
  この2つは別物で、前者は評価、後者は事実の主張にあたる。

- **禁止表現に注意。** 地の文は勢いがつくぶん「必ず」「絶対」「確実に」が混入しやすい。
  push 前に `python3 tools/check_text.py` を必ず通すこと。

- 生成された内容は一次情報（メーカー公式・実物）で裏取りしてから公開する。
  スペック表の数値は特に誤りが混入しやすい。

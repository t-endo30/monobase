## 1. 何をしたか

トップページのモックアップ画像4枚（PC全体・ヘッダー拡大・スマホ・箱の写真）をもとに、
サイト全体のデザイン更改案を作った。判断は画面を見てからしたいという要望のため、
**デプロイせず、ローカルで見るための専用画面**を用意してある。

### 確認方法

```bash
open preview/index.html
```

上部のバーで切り替える:

- **PAGE** … トップ／カテゴリー一覧／絞り込み／記事ページ／検索／お問い合わせ／404／運営者情報
- **VIEW** … PC＋スマホ／PCのみ／スマホのみ／**現行と比較**（現行トップと横並び）
- **ZOOM** … 50 / 70 / 85 / 100%

枠の中は実寸の iframe なので、スクロール・リンク・ハンバーガーがそのまま動く。

### 作り直すとき

```bash
python3 tools/build_preview.py
```

`content/site.json` と `content/articles.json` の実データを読んで
`preview/` を作り直す。**build.py は一切呼ばないし、書き換えもしない。**

### ロゴマーク

`hero-box.jpg` の等角図をそのまま図形に起こした SVG。`tools/build_preview.py` の
`LOGO_MARK` にある。箱の2面・開口部・4枚のフタという写真の構成を保っているので、
ヒーローの写真と並べても同じものに見える。

色は CSS 変数で外から差し替える:

- `--mk-body` 箱の面 / `--mk-flap` フタ / `--mk-line` フタの輪郭 / `--mk-letter` 頭文字

既定は白地向け（黒い箱＋白い頭文字）。暗いフッターでは `assets/style-v2.css` の
`.v2-footer .brand-mark` で4つとも入れ替えている。24px まで潰れずに読めることを確認済み。

### ヒーロー写真の地色について

元画像の地色は 235 前後で、紙面の `--bg:#f4f4f2` より暗い。そのまま置くと
**四角い板が浮いて見える**。CSS の `brightness` やマスクでごまかすと、
フタの先端が切れたり、地の色を変えるたびに破綻する。

そこで書き出しの時点で解決してある。照明のムラを面で推定して割り、
**地色を白(255)に正規化**したうえで、CSS 側は `mix-blend-mode:multiply` で重ねる。
multiply は白を素通しするので、地の色を何色に変えても板は出ない。

元画像を差し替えるときは、`hero-box-src.jpg` を置き換えて次を実行するだけでよい。
座標を手で決めていないので、写真が変わっても同じ手順で作り直せる。

```bash
python3 tools/prep_hero_image.py
```

## 4. 実描画で潰した不具合（再発させないこと）

Chrome ヘッドレスで実際に描画して見つけたもの。

1. 箱写真の地色が板に見える → 素材側で正規化（上記）
2. セクション見出し（PICK UP 等）が右に寄る → 右の罫線を固定幅にしていた。左右とも `flex:1`
3. PICK UP が2枠しか埋まらない → `featured` が2本しかない。不足分は新着で埋める
4. 記事のメイン画像が縦1100pxに伸びる → `.article-hero` を `aspect-ratio:16/10` ＋ `object-fit:contain`
5. パンくずの直下にカテゴリー名が重複 → 重複側を削除
6. `<mark>` が記事本文の外で既定の黄色に戻る → `.prose mark` ではなく `mark` で指定
7. **記事のリード文が `['…', '…']` とPython のリスト表記のまま出る**
   → `lead` / `summary` / `conclusion` は記事によって文字列だったり配列だったりする。
   `paras()` で両方を受けて `<p>` の並びに開いている。**build.py に取り込むときも同じ注意が要る**
8. 404 のカテゴリー枠に、記事0件の「カメラ」「ペット」が並んで行き止まりになる
   → 件数0は出さない
9. 上と同時に、枠が4列ちょうどで埋まらず、余った升が灰色の板に見える
   → 罫線を「1px の隙間＋地の色」で作っていたため。罫線はセル側の
   `border-right` / `border-bottom` に持たせ、余白には何も描かないようにした
10. 検索のタグが 139 件あり、そのまま並べると検索欄が画面外へ押し出される
   → 高さを決めて中だけ送り、下端をぼかして続きがあることを示す（`.chips.is-scroll`）
11. 引き出しメニューのカテゴリーが薄いグレーの英字書式になる
   → `.drawer a span:last-child` が、1行しかないカテゴリー側にも当たっていた。
   主メニューに `.drawer-main` を付けて、そちらだけに絞った
12. カテゴリー枠も 13 件が4列で割り切れず、余った升が灰色の板に見えた
   → 404 と同じく、罫線をセル側の `border-right` / `border-bottom` に移した
13. **フッターや本文の「プライバシーポリシー」「広告掲載について」が、
   押せなかったり別のページへ飛んだ**
   → 行き先の固定ページを作らずに `#` や `about.html` で仮置きしていた。
   本番の HTML から本文を取り出して5ページ分を書き出し、全部つなぎ直した。
   `preview/pages` のリンク切れは、書き出しのたびに数えて0本を確かめている

## 5. できている画面

トップ／カテゴリー一覧／カテゴリーの絞り込み／記事／検索／お問い合わせ／404／運営者情報。
検索はプレビューでも実際に動く（記事の索引をページに埋め込んである）。
お問い合わせは見た目だけで、送信は行わない（本番の Formspree へはつないでいない）。

固定ページ（プライバシー・免責・広告掲載・記事作成方針・サイトマップ）も
書き出しているので、フッターや本文中のリンクはすべて正しい行き先に開く。

記事ページは**公開中の全記事ぶんを書き出している**（`article-<slug>.html`）。
一覧から押した記事がそれぞれ開くので、並びや導線をそのまま確かめられる。
PAGEバーの「記事ページ」が指す `article.html` は、その中の見本1枚。

## 6. 本番への反映（2026-09-04・`design-v2` ブランチ）

`build.py` の組み立てを新デザインに置き換えた。`main` にはまだ入れていないので、
公開中のサイトは変わっていない。

- ロゴを箱の等角図に差し替え（`logo_svg()`）。ヘッダー・フッターで共用
- `header()` / `footer()` / `main_block()` を v2 に。読み込むCSSも切り替え
- カテゴリーバー・タブバー・パンくずの帯・PCの3カラムはやめた。
  同じものがヘッダーのドロップダウンと引き出しメニューに入ったため
- トップ・一覧・カテゴリー・サブ区分・新着・ランキング・検索・サイトマップ・
  固定ページ・404・お問い合わせを組み直した
- **記事本文だけは組み方を変えていない**。商品表・購入リンク・広告枠・
  提携枠・追従ボタンは収益に関わるので、マークアップをそのまま残し、
  見た目だけ旧 `style.css` から機械で移設した（344規則）。
  移設の規則は `style-v2.css` の該当区画に書いてある
- `search.js` の結果行を `.row-item` にそろえた
- 検査は `check_layout` / `check_text` / `check_images` すべて通過

### 残っている作業

1. favicon / apple-touch-icon / `og-default.jpg` を新マークで作り直す
   （`assets/img/` にある静的ファイル。`build.py` は生成していない）
2. `main.js` に、もう無い部品（`.cat-nav` / `.pick-tabs` / `.rail` など）を
   探す処理が残っている。動きに害はないが、いずれ整理する
3. `assets/style.css` は移設元の控え。落ち着いたら消す
4. カテゴリーの写真は、**管理画面から登録できるところまで済んでいる**
   （サイト設定タブ「カテゴリーの写真」→ `site.json` の `categories[].image`）。
   本番の `build.py` はまだこの欄を見ていないので、統合のときに
   `cat_finder()` / トップのカテゴリー区画で読むようにする
5. `tools/build_preview.py` は、本番と同じ組み方をもう一度書いている。
   食い違い始めたら、どちらかに寄せる

統合で移す画面は、`tools/build_preview.py` の `build_search()` / `build_contact()` /
`build_404()` / `build_subcategory()` と、`assets/style-v2.css` の
「カテゴリーの絞り込み」以降の区画。本番の `build.py` 側には対応する
`build_search()` と、`static_pages()` の 404・お問い合わせがすでにある
（フォームの項目も同じ並びにしてある）ので、中身の入れ替えで済む。
